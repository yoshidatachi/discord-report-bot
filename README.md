# Discord 報告テンプレートBot

研究室のDiscordサーバー向けの自動化Botです。大きく2つの機能があります。

1. **`/report` スラッシュコマンド**: 打つと、報告会/Gセミ用のテンプレートを自動生成します。PDFを指定すれば、タイトル・氏名・報告内容・結言を自動で読み取って埋め込みます。
2. **PDF自動反映機能**: `#報告資料` チャンネルにPDFが投稿されると、内容を読み取って `議事録` フォーラム内の該当者のスレッドに自動で反映します。

テンプレートの形式:
```
YYYY/MM/DD Gセミ(or報告会) (name)
## (タイトル)
### 報告内容

### 結言

### 議論
```

このドキュメントは「ゼロの状態から自分のPCでBotを動かせるようになる」ことを目標に、環境構築から順を追って説明します。上から順番に進めてください。

---

## 0. 全体の流れ(まずここだけ読む)

細かい手順に入る前に、全体像を掴んでおくと迷いません。やることは大きく5つです。

1. **Node.js**(プログラムを動かすための土台)をパソコンにインストールする
2. **Discord Developer Portal**でBot用のアカウント(アプリ)を作り、「トークン」という合言葉を発行する
3. このプロジェクトのファイル一式をパソコンに置き、必要な部品を `npm install` で揃える
4. `.env` というファイルにトークンなどの設定を書き込む
5. コマンドを登録して、Botを起動する

それぞれ順番に説明していきます。

---

## 1. Node.jsをインストールする

Node.jsは、このBotのプログラム(JavaScript)を実行するために必要な土台です。まだ入っていない場合は、以下の手順でインストールしてください。

### 1-1. すでに入っているか確認する

まず「ターミナル」(Windowsでは「コマンドプロンプト」または「PowerShell」)を開きます。

- **Windows**: スタートメニューで「コマンドプロンプト」と検索して開く
- **Mac**: 「ターミナル」アプリを開く(Launchpadやspotlight検索から)

開いたら、以下を入力してEnterキーを押します。

```bash
node -v
```

`v20.11.0` のようにバージョン番号が表示されればインストール済みです。「'node' は、内部コマンドまたは外部コマンド〜として認識されていません」のようなエラーが出た場合は、まだインストールされていないので次に進んでください。

### 1-2. インストールする

1. [https://nodejs.org/](https://nodejs.org/) にアクセスする
2. 「LTS」と書かれた方のボタンをクリックしてダウンロードする(「Current」ではなく「LTS」を選んでください。LTSは長期的に安定してサポートされるバージョンという意味です)
3. ダウンロードしたインストーラーを実行し、指示に従って「次へ」を押していく(基本的に設定変更は不要です)
4. インストール完了後、**一度ターミナルを閉じて開き直し**、再度 `node -v` を実行してバージョンが表示されることを確認する

## 2. Discord Developer Portalでアプリを作る

ここからは、Bot本体をDiscordに登録する作業です。**ブラウザで行うので、どのパソコンからでも作業できます**(研究室のPCである必要はありません)。

### 2-1. アプリケーションを作成する

1. [https://discord.com/developers/applications](https://discord.com/developers/applications) にアクセスし、Discordアカウントでログインする
2. 右上の「New Application」ボタンを押す
3. 好きな名前(例: 報告テンプレートBot)を入力して「Create」

### 2-2. トークンを取得する

トークンは、Botの「パスワード」のようなものです。**絶対に他人に見せたり、GitHubなどインターネット上に公開したりしないでください。** 漏れると誰でもそのBotを勝手に操作できてしまいます。

1. 左メニューの「Bot」をクリック
2. 「Reset Token」ボタンを押す(初回はここでトークンが発行されます)
3. 表示されたトークンをコピーし、メモ帳などに一旦貼り付けておく(この画面を閉じると二度と表示されないので注意)

### 2-3. Message Content Intentを有効化する

`#報告資料` チャンネルの添付PDFを読み取るために必須の設定です。デフォルトではOFFになっています。

1. 同じ「Bot」ページ内をスクロールし、「Privileged Gateway Intents」という項目を探す
2. 「MESSAGE CONTENT INTENT」のスイッチをONにする
3. 画面下部の「Save Changes」を押す

### 2-4. クライアントIDを控える

1. 左メニューの「OAuth2」→「General」を開く
2. 「CLIENT ID」と書かれた値をコピーしてメモしておく(後で `.env` に使います)

### 2-5. Botをサーバーに招待する

1. 「OAuth2」→「URL Generator」を開く
2. 「SCOPES」で `bot` と `applications.commands` の両方にチェックを入れる
3. 下に表示される「BOT PERMISSIONS」で以下にチェックを入れる
   - `Send Messages`
   - `Use Slash Commands`
   - `Read Message History`
   - `Send Messages in Threads`
4. 一番下に生成されたURLをコピーし、ブラウザの新しいタブで開く
5. Botを追加したいサーバーを選び、「認証」を押す

---

## 3. 各種IDを控える

Discordの「開発者モード」をONにすると、チャンネルやサーバーを右クリックして「IDをコピー」できるようになります。

1. Discordの設定(左下の歯車アイコン)→「詳細設定」を開く
2. 「開発者モード」をONにする
3. 以下をそれぞれ右クリックして「IDをコピー」し、メモしておく
   - Botを招待したサーバー自体 → `GUILD_ID`
   - `#報告資料` チャンネル → `REPORT_CHANNEL_ID`
   - `議事録` フォーラムチャンネル → `MINUTES_FORUM_ID`

ここまでで、以下5つの値がメモできているはずです。

- `DISCORD_TOKEN`(2-2で取得)
- `CLIENT_ID`(2-4で取得)
- `GUILD_ID`(3で取得)
- `REPORT_CHANNEL_ID`(3で取得)
- `MINUTES_FORUM_ID`(3で取得)

## 4. プロジェクトファイルを配置する

1. 配布された `discord-report-bot.zip` をダウンロードする
2. デスクトップなど、分かりやすい場所にダブルクリックで解凍する
3. ターミナルで、解凍してできたフォルダに移動する

```bash
cd discord-report-bot
```

(パスが分からない場合、Windowsならフォルダをエクスプローラーで開いてアドレスバーに `cmd` と入力しEnterを押すと、そのフォルダの中でコマンドプロンプトが直接開きます)

4. 必要な部品(discord.js、pdf-parseなど)をインストールする

```bash
npm install
```

少し時間がかかりますが、これで完了です。

## 5. .envファイルを作成する

トークンなどの設定値を書き込む専用のファイルを作ります。

1. `.env.example` というファイルをコピーして `.env` という名前で保存する

```bash
# Mac / ターミナル
cp .env.example .env
```
```bash
:: Windows コマンドプロンプト
copy .env.example .env
```

2. できた `.env` をメモ帳などのテキストエディタで開き、先ほど控えた5つの値を書き込む

```
DISCORD_TOKEN=ここにトークン
CLIENT_ID=ここにクライアントID
GUILD_ID=ここにサーバーのID
REPORT_CHANNEL_ID=ここに#報告資料のID
MINUTES_FORUM_ID=ここに議事録フォーラムのID
```

保存して閉じてください。

**注意**: `.env.example` は「例」を書いたファイルであり、これ自体には本物のトークンを書きません。必ず自分でコピーして作った `.env` の方に書き込んでください。`.env` は他人と共有しないでください。

## 6. スラッシュコマンドを登録する

Discord側に `/report` コマンドの存在を教える作業です。**設定を変更した時、または最初の1回だけ**実行すればOKです。

npm run deploy

## 8. 使い方

### 手入力の場合
```
/report type:Gセミ title:実験結果まとめ name:田中
```

### PDFから自動入力する場合
```
/report type:報告会 pdf:(報告書PDFを添付)
```
コマンド実行時に `pdf` オプションでファイルを選択すると、PDF内のテキストからタイトル・氏名・報告内容・結言を自動抽出してテンプレートに埋め込みます。

オプション一覧:
- `type`(必須): 「Gセミ」か「報告会」を選択
- `pdf`(任意): 報告書PDF。指定するとタイトル/氏名/報告内容/結言を自動抽出
- `title`(任意): タイトル。指定した場合はPDFからの抽出結果より優先
- `name`(任意): 発表者名。省略時は PDFから抽出 → コマンド実行者の表示名 の順で採用

**前提となるPDFのフォーマット**(報告内容・結言の自動抽出に必要)
- 数行目までにタイトルがある
- `YYYY/MM/DD` 形式の日付がある
- その次の行に学籍番号+氏名などの発表者名がある
- `N. 報告内容` や `N.N. 報告内容` のように、数字+区切り記号+見出し文字列という形式で「報告内容」「結言」の見出しが本文中に存在する

このフォーマットと異なる報告書だと自動抽出できないことがあります。その場合は `title` / `name` オプションで上書きするか、手入力で運用してください。

## 9. PDF自動反映機能について

`REPORT_CHANNEL_ID` で指定したチャンネル(`#報告資料`)にPDFが投稿されると、Botが自動で:

1. PDFからタイトル・氏名・報告内容・結言を抽出
2. `議事録` フォーラム内で「`(氏名)_議事録`」という名前のスレッドを検索
3. **見つかった場合**: そのスレッドに ①Discordのネイティブ「メッセージ転送」機能で元のPDFメッセージを転送 → ②議事録テンプレートを新規メッセージとして投稿、の順で2件のメッセージを送信(再アップロードではなく転送のため、ファイル名も完全に保持されます)
4. **見つからなかった場合**: 新規スレッドは作成せず、`議事録` フォーラム内の **`ERROR`** という名前のスレッドにテンプレートを投稿し、投稿元チャンネルに通知します。事前にフォーラム内に `ERROR` という名前のスレッドを作成しておいてください(完全一致で判定しています)。通知が来たら、`ERROR` スレッドの投稿を該当者のスレッドへ手動で振り分けてください。

日付・種別(Gセミ/報告会)は PDFの内容 → ファイル名(`YYYY-MMDD_種別_氏名.pdf`) の順で判定します。

### 種別(Gセミ/報告会)の判定について【重要な既知の制約】

Discordの仕様上、添付ファイルのファイル名に含まれる**日本語部分が失われる/文字化けすることがある**ことが分かっています(絵文字や特定の記号との組み合わせなどで発生しやすいようです)。このため、以下のような2段階の判定方式にしています。

1. まずファイル名全体から「Gセミ」「グルセミ」「報告会」等のフルテキストとしての一致を試みる(正確)
2. 1で見つからず、かつファイル名に半角/全角の **`G`** が1文字でも含まれていれば「Gセミ」とみなす(フォールバック)
3. 1にも2にも該当しなければ種別不明として扱われ、デフォルトの「報告会」が採用される

**運用上のポイント**: 日本語(「グルセミ」など)がまるごと失われた場合、2の"G"フォールバックも効かないため「報告会」に誤判定される可能性が残ります。これを避けるため、**ファイル名の種別部分は「Gセミ」(半角G)を使うことを推奨します**。半角/全角の"G"はこの現象の影響を受けにくく、フォールバックで確実に拾えます。

氏名に学籍番号(例: `AC21059 吉田匠吾`)が含まれる場合は自動で氏名部分のみを使用します。

**制約1**: アーカイブ済みスレッドの検索は直近100件程度が対象です。長期間放置されたスレッドは見つからず、`ERROR` スレッドに投稿される可能性があります。

**制約2**: 「転送」は元のメッセージ単位で行われます。1つのメッセージに複数のPDFが添付されている場合、転送するとそのメッセージに含まれる添付ファイル全てが一緒に転送されます(通常は1メッセージ1PDFの運用を想定しているため、基本的には問題になりません)。

## 11. トラブルシューティング

### `npm install` でエラーが出る
- Node.jsが正しくインストールされているか、`node -v` で確認してください
- インターネットに接続されているか確認してください

### `npm run deploy` でエラーが出る
- `.env` の `DISCORD_TOKEN` と `CLIENT_ID` が正しいか確認してください
- Discord Developer Portal側でBotが正しく作成されているか確認してください

### `npm start` は動くが `/report` が反応しない
- `npm run deploy` を実行し忘れていないか確認してください
- Discord側への反映に数分かかることがあるので、少し待ってから再度試してください

### PDFを投稿しても議事録に反映されない
- Botがオンラインになっているか確認してください
- `.env` の `REPORT_CHANNEL_ID` が投稿先チャンネルと一致しているか確認してください
- Discord Developer PortalでMessage Content IntentがONになっているか確認してください(2-3参照)
- ファイルの拡張子が `.pdf` になっているか確認してください

### 種別(Gセミ/報告会)が意図と違う
- 「9. PDF自動反映機能について」の判定ロジックの制約を参照してください
- ファイル名の種別部分に半角/全角の「G」を含めることを推奨します(グルセミより「Gセミ」の方が確実です)

より運用寄りのトラブルシューティング(Botが落ちていた時の対応、pm2の使い方など)は `引き継ぎガイド.md` を参照してください。
